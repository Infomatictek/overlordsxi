## Mappings that need extra care

- Server stores the job's numeric catalog branch in OX_SPEC_<JOB>. A fresh snapshot must record raw numeric value, resolved key, canonical display name, crystal item if nonzero, and all legitimate aliases. Preserve DNC 2/3/4, MNK 2 Chi Weaver and 3 Black Belt, PUP 2 Animist and 3 Pugilist. Compare a captured character before/after profile enable, relog, sync and disabling the feature.
- Spellblade uses spell IDs 363/364 for Runic Bolt/Sever. The old helper contains a permanent removal path for 754/755. The new visibility/approval code must never reuse that path for ordinary Soul changes, and must never reassign those legacy slots from this inventory alone. Snapshot learned spells first.
- Shinobi uses existing JA 487/488 (Metrics 999/1000), Kagemusha 443/444. The [Huntsman server redesign](https://github.com/Infomatictek/overlordsxi/tree/18bb7e3168d825e715f21fd557a8464fb038275d) also reserves 489/490 and its [launcher counterpart](https://github.com/Infomatictek/overlordsxi-launcher/tree/09c60a9f86dcb23d850d0a46bfccae603b01bef6) labels 1001/1002. New design work cannot claim any of these four Shinobi/Huntsman slots.
- For Vanguard, SQL dispatch uses aegis_protocol / gyro_slam, generic Metrics resources still name them Aegis Protocol / Gyro Slam, and the user-facing Metrics override uses Clockwork Bulwark / Hydraulic Slam. Fix mismatched surfaces via a display mapping, keep the dispatch names and ability IDs.
- Separate the real server spell ID from the example in the Soul-actions addon. Its demo registers Tsunami on ID 1 for demonstration. A real water spell mapping must be verified against the target client's spell resources and server spell table. Use the owner's intended Soul identity; never publish that demo slot as an entitlement.
- The generated wiki assigns 61 to both “Iron Counterstance” and “Call Wyvern.” The MNK registration looks up the COUNTERSTANCE jobAbility enum. Bind the installed enum and dispatch for each job; never allocate solely from the wiki.
- The launcher includes Flintlock HUD declarations mentioning Black Powder and Load Powder. Their presence supplies no evidence of compatible dual-pistol server events. The independent owner must identify which fields the live project emits before any of those indicators is presented as real.
- The Chi Weaver prose lists negative Attack% and WS penalties. The central non-damage-tier passive builder explicitly skips negative ATTP, RATTP, MATT, MACC and ALL_WSDMG_ALL_HITS. Compare the actual net role output and scoped effects in combat. Never add those guide penalties back as new passives.

## Allocation procedure for new profiles

Capture the installed, versioned SQL tables for abilities, spells, traits, WS and recast IDs, plus Lua enum/fallback values, C++ patch IDs, client DAT rows, Soul-action profiles, native labels and staged feature reservations. Index by kind and ID; shared use by different Soul profiles is legal only if each mapping is explicitly keyed and ordinary job behavior stays intact. Check job restriction, level loan, recast grouping, row width, localized text and existing character records. Record the selected ID, display source and owning module in the implementation PR. An absent row here does not certify a free slot. Trait capacity is limited to the existing engine range; prefer existing hooks over new traits that only carry a display label. No new numeric allocations are made by these designs.
